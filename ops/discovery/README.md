# Alpine 自动发现镜像

从网络引导的 Alpine 在内存中运行。它读取本机硬件，上报后停在结果屏。采集不挂载磁盘、不写硬盘，也不需要服务器管理网或管理口凭据。电源、风扇等数据可通过 Linux 传感器和本机管理芯片接口读取。

## 构建

在对应架构的 Linux 上执行。需要 Bash、curl、GNU tar、GNU cpio、gzip 和 root 权限。构建固定使用 Alpine 3.24.4 的官方最小根文件系统，校验预先记录的 SHA-256。软件包来自 Alpine 3.24 的签名软件源，实际版本写入 `packages.txt`。

```sh
sudo bash ops/discovery/build.sh x86_64 /tmp/lober-discovery/x86_64
# 在 ARM64 Linux 上构建 ARM64 镜像
sudo bash ops/discovery/build.sh aarch64 /tmp/lober-discovery/aarch64
```

构建会把网卡驱动、依赖和固件打进 `initramfs.gz`，检查每个目标网卡驱动及其声明的固件。镜像下载后即可加载网卡，无需用尚未识别的网卡下载驱动。默认清单覆盖常见 Intel、Mellanox、Broadcom、Realtek、ENA 和虚拟机网卡。清单见 `nic-drivers.txt` 和 `firmware-files.txt`。加驱动时，用 `EXTRA_NIC_MODULES` 和 `EXTRA_FIRMWARE_PACKAGES` 提供以空格分隔的模块名、固件包名。换内核或扩展清单后，重新测试目标机器的启动网口。

镜像选用目标内核提供的通用内存纠错驱动，x86-64 另保留常见 AMD 和 Intel 平台的驱动。`edac-drivers.txt` 列出本次构建保留并尝试加载的驱动。可用 `EXTRA_EDAC_MODULES` 指定目标机器所需的驱动模块，多个模块用空格分隔。是否能读到计数，以目标机器上报为准。

如需读取部分 Broadcom 阵列控制器的成员盘和逻辑盘映射，可设置 `STORCLI_BINARY` 指向适合目标架构的本机工具，并用 `STORCLI_SHA256` 提供校验和。这个工具由使用方根据厂商条款准备，默认镜像不携带它。镜像只对该工具执行 `show` 查询。没有兼容工具时，报告仍包含控制器和系统可见盘，并标明未读取的成员盘信息。

## 主机详情能看到哪些属性

打开「主机清单 → 查看详情 → 硬件部件清单」。这里显示这台主机最近一次详细上报的时间、部件、数据来源和各字段的读取结果。报告时间取服务端成功接收的时间。

| 部件 | 可读属性 |
| --- | --- |
| 整机、机箱 | 厂商、型号、整机序列号、整机唯一标识、整机料号、资产标签，机箱厂商、序列号、版本和料号 |
| 主板、启动固件 | 主板厂商、型号、序列号、版本，启动固件厂商、版本、日期，本次启动方式，安全启动开启或关闭 |
| 管理芯片、安全芯片 | 管理芯片厂商、产品型号或编号、固件版本，最近最多 20 条设备事件及原始时间。每颗安全芯片的设备名及规范版本，如 TPM 2.0 |
| 处理器 | 架构、型号、插槽数、总线程数、每插槽物理核数、最大频率。固件提供逐插槽数据时还可读插槽名、厂商、各自的物理核数和线程数、当前与最大频率、状态；系统的一层数据缓存、一层指令缓存、二层和三层缓存，以及固件登记的各缓存名称与容量 |
| 内存 | 系统可用总量。逐插槽显示位置、通道、空槽状态；已安装内存条的容量、类型、额定速率、当前速率、厂商、料号、序列号。支持纠错的设备还可读可纠正和不可纠正错误次数。能确认插槽时显示到插槽，也可查看控制器总计 |
| 系统可见磁盘、背板 | 设备名、类型、容量（字节）、型号、序列号、接口、固件、机柜内盘位、介质类型、系统存储路径、自检健康状态、已用寿命百分比、通电小时、温度、介质错误次数 |
| 阵列控制器 | 控制器编号、型号、序列号、固件、板载缓存容量、缓存保护电池或电容状态 |
| 阵列逻辑盘 | 控制器编号、阵列组与逻辑盘编号、名称、阵列级别、容量、状态 |
| 阵列物理盘 | 控制器编号、机箱与盘位、所属阵列组、型号、序列号、接口、介质、容量、固件、状态、热备角色、温度、介质错误次数；正在重建时显示该成员盘进度。阵列组编号可用于核对受影响的逻辑盘 |
| 网卡、光模块 | 接口名、硬件地址、驱动、固件、是否接通、是否启动网口、端口最高支持速率、当前协商速率、模块型号（厂商料号）和模块序列号。每个已识别网口还有收发错误、丢包和接收校验错误的累计读数 |
| 光纤存储卡 | 每个端口的设备名、端口全球唯一标识（WWPN）、节点全球唯一标识（WWNN）、端口状态、当前协商速率和支持速率列表 |
| 扩展卡、图形与计算加速卡 | 总线地址、设备描述、厂商编号、设备编号、物理插槽、驱动、固件、扩展卡类别编号。这些总线属性也适用于能关联到总线的网卡与存储控制器。扩展卡支持时显示可纠正及不可纠正链路错误次数。图形与计算加速卡还可读型号、显存容量（字节）、序列号、当前实际使用的通道数和链路速率 |
| 电源 | 位置、厂商、名称、料号、序列号、额定功率、状态、所属电源组、版本。本机管理接口还可提供电源状态及冗余传感器的名称和原始记录 |
| 风扇、温度 | 传感器名称、风扇每分钟转数、温度（摄氏度）、本机管理芯片的风扇和温度传感器记录 |

设备自己报告的零值会照常显示，例如介质错误为 0。缺项会显示原因，例如端口未接通、工具未安装、查询超时、驱动不支持或固件未提供。旧报告只包含原镜像当时上报的字段。

错误计数是 Linux 在本次启动中读取的设备或驱动累计值。驱动可能为未填充的网口计数返回 0。管理芯片事件是设备保存的历史记录，时间和时区以设备提供的信息为准。读到空日志时显示「无记录」。

磁盘寿命按设备公开的已用百分比读取。阵列只暴露逻辑盘时，物理成员的寿命与通电小时可能不可读。光模块资料取决于网卡驱动。显存和序列号取决于显卡驱动；支持的 AMD 驱动可直接提供显存，NVIDIA 厂商查询需要匹配的驱动和本机 `nvidia-smi`。标准镜像未内置该厂商工具。光纤卡和显卡有时还需要厂商固件包，可通过构建参数 `EXTRA_FIRMWARE_PACKAGES` 补入适合机型的包。

已登记主机使用「请求硬件采集」，下次从网络启动后刷新报告。部署时将 `preview.inventoryKernel` 和 `preview.inventoryInitrd` 指向上述新版制品。自动发现使用下节的镜像配置。只更换控制台不会补齐旧报告中的数据。

服务首次升级时会补建 `host_hardware_reports` 表，每台主机保留最近一次主动采集的详细报告。自动发现的报告仍在 `host_discoveries` 表中。回退应用时可切回旧服务与旧采集镜像，保留新表。恢复数据库时，从同一份备份恢复主机和报告，以保持序列号对应。

## 接入机器网关

把目标架构的 `vmlinuz` 和 `initramfs.gz` 放到 `preview.artifacts` 指向的制品目录。下面示例启用 x86-64，ARM64 在同一映射增加 `aarch64` 项。

```yaml
machine:
  enabled: true
  discovery:
    enabled: true
    allowedNetworks: [192.0.2.0/24]
    images:
      x86_64:
        kernel: discovery/x86_64/vmlinuz
        initrd: discovery/x86_64/initramfs.gz
```

把示例网段换成实际装机网。Lober 按直连来源地址判断网段。只有代理入口已按实际来源地址限制机器请求来自装机网时，才把直接连接 Lober 的代理单个地址加入 `allowedNetworks`，IPv4 写成 `/32`，IPv6 写成 `/128`。Lober 不采用代理转发的来源地址。

在装机网的 iPXE 脚本里沿用现有引导地址，附加启动网口硬件地址。`netX` 是 iPXE 内置设置，代表最近打开的网口，`dhcp` 成功后再读取它。把示例域名换成 Lober 网关地址。

```ipxe
#!ipxe
dhcp || exit
chain http://lober.example.test/v1/boot?sn=${smbios/serial:uristring}&arch=${buildarch}&firmware=${platform}&mac=${netX/mac:hexhyp} || exit
```

采集系统优先通过启动网口获取地址。镜像找不到网卡时，结果屏会显示能识别的网卡硬件编号和固件加载错误。已经报到但始终传不上报告时，控制台仍有报到记录。现场结果屏只显示阶段和失败状态，上传凭据不会输出到日志。

## 验证

```sh
python3 -m unittest discover -s ops/discovery -p 'test_*.py'
python3 ops/discovery/smoke.py /tmp/lober-discovery/x86_64
python3 ops/discovery/smoke.py /tmp/lober-discovery/x86_64 --registered
```

第二条命令使用 QEMU 的 iPXE 网卡引导和本机测试接收端。检查虚拟机从 iPXE 下载镜像、Alpine 获取网络地址、上传带启动网口的报告并停在结果屏。用 `--direct` 可单独排查内核和内存镜像。实际部署还需验证 Lober 接收端与控制台、目标型号驱动、阵列和传感器。
