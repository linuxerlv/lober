# Lober 装机平台企业级测试指南

本文档规定了 Lober 装机平台在进入正式交付前需要完成的测试内容。

装机平台一旦出错，轻则几十台服务器卡在安装界面，重则格错硬盘、把宿主机磁盘撑爆。因此测试分为**必须做的测试**（上线硬门槛）和**可选做的测试**（按客户规模和机房环境选做）。

---

## 一、 测试与分支流转对应关系

结合项目分支规范，不同阶段做不同深度的测试：

| 分支阶段 | 目标 | 必跑测试项 |
| :--- | :--- | :--- |
| **功能分支 -> `develop`** | 保证单模块功能正常、不破坏原有代码 | 单元测试、前端类型检查、代码规范检查（`make check`） |
| **`develop` -> `test`** | 保证多模块合并后配合正常、真数据库不出错 | 真实 PostgreSQL 集成测试、镜像导入与清理测试、配置渲染核对、前后端联调 |
| **`test` -> `preview`** | 满足企业级稳定性和性能要求 | 批量装机并发测试、异常中断恢复测试、权限与安全测试、虚拟机真机安装验收 |
| **`preview` -> `main`** | 最终人工验收通过，准备正式发版 | 部署与升级演练、核心业务主流程抽检 |

---

## 二、 必须做的测试（上线硬门槛）

以下 6 类测试在合入 `preview` 之前必须全部通过。

### 1. 自动化基础检查（每次提交必跑）

先用自动化工具把低级错误拦住：

1. **后端全量检查：** 在项目根目录运行 `make check`，确保代码格式、静态检查、普通测试、并发竞争检查（race）、Linux 编译和依赖注入（Wire）全部通过。
2. **真实 PostgreSQL 测试：** 配置 `LOBER_TEST_PG_DSN`（或写入 `.pgtest.dsn`），运行 `go test ./...`，验证真实数据库下的读写、事务回滚和表结构迁移。
3. **前端检查与测试：**
   * 类型检查：`pnpm --filter @vben/web-ele typecheck`
   * 单元测试：`pnpm exec vitest run`
   * 打包验证：`pnpm build:ele`

### 2. 装机配置与脚本生成测试（`internal/render`）

生成的应答文件或引导脚本错一个符号，机器就装不上系统。

* **多系统应答文件核对：** 验证生成的 Linux（Kickstart / Preseed / Cloud-init 等）和 Windows（`Autounattend.xml`）配置文件格式正确，与标准答案（`testdata` 黄金文件）完全一致。
* **引导菜单生成（`menu`）：** 验证不同主机状态、不同引导方式下生成的网络引导菜单正确无误。
* **变量替换与特殊字符过滤：**
  * 测试主机参数、全局参数、网卡配置、钩子脚本（`hooks`）拼接是否正确。
  * 在密码、主机名、自定义参数里填入空格、单双引号、换行符、`$`、`&`、`;` 等特殊字符，确保生成的脚本不会语法报错，也不会被恶意注入命令。

### 3. 镜像导入、解析与清理测试（`internal/iso` / `artifact-sets`）

系统镜像体积大（几个 GB 到十几个 GB），是平台最容易出故障的环节。

* **三种导入方式全覆盖：**
  1. 本地文件路径导入（`local`）
  2. 网页大文件上传（`upload`）
  3. 远程网址拉取（`remote`）
* **系统自动识别（`identify` / `wim`）：**
  * 导入主流 Linux 镜像（Ubuntu、Rocky、CentOS、麒麟、统信等）和 Windows 镜像，检查识别出的系统类型、版本号、架构（x86_64 / arm64）是否准确。
  * 故意上传损坏的 ISO、空文件、或把普通压缩包改名为 `.iso`，系统必须明确报错拦截，服务不能崩溃。
* **中断恢复与垃圾文件清理（重点检查）：**
  * **服务重启恢复：** 在镜像解压或导入到一半时，直接重启 Lober 服务，验证重启后能否自动恢复或清理半成品（`recover` / `shutdown_resume`）。
  * **彻底删除验证：** 在后台删除一个镜像后，去服务器磁盘目录检查对应的 ISO、解压出的内核文件和 WIM 文件是否真正删干净，绝不能留残余文件占满磁盘。
* **远程拉取防内网探测（`ssrf`）：**
  * 在远程导入地址中输入 `http://127.0.0.1`、`http://localhost` 或局域网内部地址，系统必须拒绝访问。

### 4. 装机任务与快照隔离测试（`internal/core`）

* **配置快照防篡改（`snapshot`）：**
  1. 创建一个装机任务并激活。
  2. 立刻去后台修改该任务用到的装机模板、全局参数或钩子脚本。
  3. 模拟机器拉取装机配置，验证机器拿到的依然是任务激活那一刻的旧配置，不受中途修改影响。
* **主机准入与状态流转（`admission` / `activation`）：**
  * 模拟一台新机器从首次上报硬件信息、准入审批、绑定任务、拉取配置、上报安装进度，到最终完成并生成装机报告（`reports`）的完整闭环。
  * 模拟机器重复请求同一个接口，或装机中途重启重装，验证任务状态不会卡死或错乱。

### 5. 管理后台与防呆保护测试（`console` / `web`）

* **7 大核心页面走查：** 逐一操作主机（`hosts`）、任务（`tasks`）、模板（`templates`）、钩子（`hooks`）、工具（`tools`）、制品集（`artifact-sets`）、报告（`reports`）的增删改查。
* **关联占用防误删：**
  * 尝试删除正在被装机任务使用的镜像、模板、钩子或工具，系统必须弹窗拦截并提示“正在被某某任务使用，无法删除”。
* **登录与越权检查：**
  * 未登录状态下直接访问后台页面或调用后端接口，必须全部拦截并跳回登录页。

### 6. 批量装机并发测试

机房装机通常是几十台服务器同时通电开机。

* **并发请求压测：** 连上 PostgreSQL 数据库，用压测工具模拟 **50 台机器在同一秒** 请求引导菜单、拉取应答文件和钩子脚本、上报装机状态。
* **通过标准：**
  * 所有请求 100% 成功，无 `500` 报错，无数据库死锁。
  * 95% 的配置拉取请求在 1 秒内返回。
  * 压测结束后内存能够正常回落，无明显内存泄漏。

## 三、 可选做的测试（按交付场景选做）

根据目标客户的机房规模、网络环境和验收严苛程度，挑以下测试执行：

| 测试项 | 具体怎么测 | 适用场景 / 建议执行时机 |
| :--- | :--- | :--- |
| **1. 虚拟机真机全自动装机** | 建 2 台空白虚拟机（1 台装 Linux，1 台装 Windows），通过网络引导（PXE/iPXE）连上 Lober，全程不人工干预，看能不能自动装完进系统、跑完钩子脚本并上报成功 | **强烈建议每个正式版本发布前做一次**。代码测试代替不了真机引导验收 |
| **2. 磁盘满载极限测试** | 把 Lober 所在服务器的数据盘塞到只剩 2GB，然后上传一个 5GB 的系统镜像，看系统能不能提前提示“磁盘空间不足”并清理临时文件 | 客户服务器磁盘空间有限，或者无人值守运维的机房 |
| **3. 弱网与断网重连测试** | 上传大镜像或远程下载镜像时，故意拔掉网线 10 秒或把网速限制在 1MB/s，测试报错提示是否清晰、恢复网络后重试是否正常 | 跨机房远程拉取镜像、或者现场办公网络不稳定的环境 |
| **4. 百台机器同时下载大文件** | 模拟 100 台机器同时从 Lober 下载内核（vmlinuz/initrd）和系统安装文件，在网卡带宽打满的情况下，测试管理员还能不能流畅打开网页后台 | 客户需要一次性整柜（上百台服务器）同时装机时 |
| **5. 物理服务器双引导兼容测试** | 找华为、戴尔、浪潮等真实物理服务器，分别在传统引导（Legacy BIOS）和新式引导（UEFI）模式下跑通装机流程 | 交付给政企、金融、运营商等硬件型号复杂的机房时 |
| **6. 7×24 小时长时间运行测试** | 让服务连续运行 3~7 天，期间定时跑装机任务和镜像导入删除，观察内存占用、数据库连接数和磁盘空间是否稳定 | 要求全年无休运行、不允许定期重启服务的生产环境 |
| **7. 第三方安全渗透与漏洞扫描** | 使用漏洞扫描工具扫描前后端依赖包和接口，检查是否有高危漏洞、密码明文传输或越权漏洞 | 政企、银行等验收时要求提供安全扫描报告的项目 |

## 四、 上线前最终核对清单（Checklist）

在把代码从 `preview` 合并到 `main` 之前，逐条打勾确认：

- [ ] `make check` 全部通过，无警告、无报错
- [ ] 连真实 PostgreSQL 数据库跑通全部后端测试
- [ ] 前端 `typecheck`、`vitest`、`build:ele` 全部通过
- [ ] 本地、上传、远程 URL 三种方式导入 Linux 和 Windows 镜像均成功
- [ ] 删除镜像后，服务器硬盘上的对应大文件已确认清理干净
- [ ] 任务激活后修改模板，已确认不影响正在执行的装机任务（快照生效）
- [ ] 正在使用中的镜像、模板、钩子无法被直接删除
- [ ] 50 台机器并发拉取装机配置与上报状态测试通过，无报错卡死
- [ ] 至少用虚拟机真机跑通 1 次 Linux 和 1 次 Windows 全自动无人值守装机
- [ ] 空白环境首次安装部署，以及从旧版本升级到新版本演练通过
