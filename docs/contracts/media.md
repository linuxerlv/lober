# 镜像与后台作业兼容契约

本文件固定第四阶段迁移前的行为。公开请求以控制台路由描述和现有响应为准；保存约定以 `domain/repository` 为准。本文件不增加新的请求格式或业务能力。

迁移前核对来源包括原 `cmd/lober/{supervisor,deletion}.go`。当前实现位于 `application/media`、`domain/media`、`infrastructure/media`；网页入口为 `interfaces/console/{isos,isosource}.go`，数据库约定仍是 `domain/repository/{isos,sources}.go` 与 `infrastructure/persistence/pgstore/{isos,sources}.go`。

## 1. 身份、输入与错误

五种有效角色可读；只有 `admin` 可写。`operator` 不持有 `iso:write`。失效会话、禁用账号、无效角色和必须改密检查沿用控制台规则，拒绝时不进入业务处理。

这是现有权限，不扩大权限。计划初稿曾写“admin/operator 可写”，已在 `a5b02a8` 按真实权限和现有五角色测试更正。

镜像编号接受 `^[a-z0-9][a-z0-9-]{0,63}$`；非空来源角色接受 `^[a-z][a-z0-9_]{0,31}$`，再检查是否是当前系允许的额外角色。名称不自动裁剪、改大小写或去重，只要求可保存文本；族与系必须有效且对应。

外部来源种类是 `url/path/upload`，内部对应 `remote/local/upload`。`upload` 文件名只是标签，预检清空地址，大小必须为正数。`url` 可登记未知大小 0；路径和网址不能为空。大小不可为负；摘要只能为空或 64 位小写十六进制。文本必须有效且不含零字节；来源错误文本最多 4096 字节。

普通非法输入返回 400；缺失返回 404；版本、状态、重复、不可改或引用冲突返回 409。`ProblemsError` 保持 422；领域问题沿用现有类别映射及问题代码。内部错误返回 500 和通用中文消息，不在响应暴露路径或连接信息。调用方按错误类别和问题代码处理，不能匹配错误文字。

成功响应状态为 200，外层为 `code/data/message`。读操作无审计；网页上传分片无审计。业务写入和它自己的审计必须在同一事务提交，零值来源审计不产生记录。通知只提示重新扫描持久化事实，不承诺每次唤醒都被单独处理。

网页审计记录当前用户名、路由动作、注入时钟给出的时间；仓储把目标补为 `iso` 和镜像编号。这些镜像入口的 detail 为空。后台进度和区间保存继续用零值审计，不伪造用户操作。

前缀为 `/console/v1/isos`。表中的“写”均限管理员；所有入口都保留原会话检查和请求取消上下文。

## 3. 创建、登记与余量

角色 `""` 是主来源，创建必须恰好一个。重复角色在该来源自身字段检查前返回400。额外角色只接受 `catalog.ExtraSourceOf` 登记的角色，不增加新的镜像格式或来源要求。

预检只检查可保存的来源字段。实际登记再检查当前镜像、允许本地根、网址协议、域名解析后的所有地址及重复来源。有效格式的回环网址会在创建镜像后被网络安全检查拒绝；任一来源预检非法，则整个请求还没有创建记录。

余量按所有非 `path` 来源的 size 累加，溢出400。合计0不查余量；非0仍读取原能力的两个余量值，但只比较 staging，缺少时给 `iso_space_insufficient`。不改成两个目录分别预留。本地原件就地读，不复制、不删除。

镜像创建和每条来源登记分别提交。第二来源失败时保留镜像、第一来源和对应两条 `iso.create` 审计，返回失败并保留 `Location`，失败来源不落库。请求取消也不撤销此前已经提交的操作。未创建前失败则没有 Location。

`Register` 保留旧同步调用者的补源流程；`RegisterQueued` 在失败镜像补额外来源时使用 `SaveSourceAndAcquire`。该事务同时保存来源、镜像 acquiring 状态和审计，审计或排队失败都撤销，不得只保存一半。提交后才 Wake。

## 4. 查询、区间和上传

镜像列表按名称字节序、再编号排序；支持游标与页码，两种模式不能混用。默认每页20，最多500；空 items 是数组，next 无下一页时为空串；只有页码模式有 total。来源按角色字节序，区间按起点递增并合并重叠、相邻部分。

网页 `sourceProgress.ranges` 是**已确认区间**，含 start/length；同时返回 role、外部 kind、totalSize、fetched、state、error、rev。空来源和空区间为数组。每来源区间读完后核对 Rev，不同则重读；最多3轮，仍变化返回409。

旧 `Sources.Progress` 的 `Missing` 是**尚缺区间**。例如总长12，已确认 `[4,10)`，网页 ranges 为 `{start:4,length:6}`，旧 Missing 为 `{0,4}` 和 `{10,2}`。未知大小、已 fetched 来源不臆造缺片。两者不能直接换名替代。

`Content-Range` 严格接受 `bytes 起点-终点/总长` 或 `bytes 起点-终点/*`。数字只含十进制字符，终点包含在分片内；不能倒序或溢出。总长已给出时必须与登记总长一致，范围不可越界，已声明的 ContentLength 与真实读取长度都要匹配。

来源种类先于边界检查：非上传来源即使同时越界也返回409。缺失来源即使同时越界也先404；坏角色先400。范围语法错误统一使用 `ConsoleContentRange` 中文消息，不能改成普通非法输入消息。

先暂存分片并检查长度、重叠字节，再修改确认文件。`SaveRange` 在来源行锁内保存区间、更新并集计数和 Rev；短重传不能撤销较长已确认片段。字节写入和数据库不是一个事务，不承诺整次上传失败后所有临时文件都不存在，但拒绝的错误分片不能污染已确认字节、区间或版本。

完成响应丢失后，相同字节重传仍成功。完成前重新核对来源 fetching 状态及 Rev；并发取消不能被旧进度覆盖。取消后不能继续发布为完成。网页上传不写审计；旧直接能力传入有效非零审计时保留原审计行为。

## 5. 取消、重试和关闭

Cancel 先保存来源 cancelled，再取消本实例正在读取的上下文，不等待被文件锁阻塞的读取完成。多个来源逐条提交，不承诺全来源一起成功或一起失败；冲突重读16轮后返回409。

Retry 只重置 failed/cancelled。仓储事务把 fetched/error 和上传区间一起清零。非本地文件先暂存避开旧字节；审计失败恢复文件，成功提交后删除暂存副本。本地原件不改。重试逐来源处理，也不提供跨来源事务。

用户 Cancel 与作业上下文结束不同。关闭或超时保留 fetching 和已有断点，让下一实例恢复；不会把关闭写成用户取消或下载失败。取消上下文贯穿来源读取、复制和工具操作，已提交记录仍保留。

## 6. 导入、发布与未知提交结果

Import 是阻塞能力；网页重新导入走 `RequestReimport` 保存事实后立即返回。只有全部已登记来源和必需来源 fetched 才允许排队。主来源是排队请求的稳定载体；来源版本、镜像版本、acquiring 状态和 `iso.reimport` 审计一次提交。

导入读取实际内容，核对大小、摘要、系、版本、架构、额外网络介质及必需制品。保持原问题代码，例如 `iso_content_mismatch`、`iso_media_unrecognized`、`iso_series_mismatch`、`iso_extra_source_invalid`、`iso_artifact_missing`。提取器和镜像格式不在此任务改写。

所有来源在复制结束后再次核对。制品先写目的盘上的临时兄弟目录，再发布；已有其他镜像或拥有者的同平台内容不覆盖。重复 ready 导入409，deprecated 不可变。摘要去重、版本检查和制品完整性仍由原仓储保护；系统状态更新不额外记用户审计。

文件已发布而数据库提交响应丢失时，用独立于取消的最多5秒读取确认。只有确认同摘要、同 artifacts、ready 才按成功返回；结果未知时保留发布文件，不能用一次提交错误推断回滚并删除可能已提交的制品。

## 7. 删除、清理与仓储边界

删除准备和来源登记共用闸门，快照必须覆盖已经登记的来源。先把完整镜像和非 nil 来源数组同步保存，再执行版本与引用保护下的数据库删除及审计。快照失败不得先删除行或字节。

删除确认成功后才清理。删除结果未知时保留快照；确认镜像仍在时撤销快照且不删字节。恢复只在确认记录不存在时清理；读取失败或未知时不清理。清理失败保留日志供重启重试，成功清理可重复调用。

只清理该编号拥有的暂存和发布内容。本地原件、符号链接外目标、其他镜像和其他拥有者目录保留。清理不产生第二条删除审计。

`CreateISO` 返回 acquiring、Rev=1；`UpdateISO` 不允许改名称/族/系，废弃不可逆。来源新建须 pending、Rev=0、零进度和空错误，返回Rev=1。更新核对原Rev，种类、地址和摘要不可更改。来源父镜像行锁串行保护新键登记；版本冲突不得靠进程锁代替数据库检查。

`SaveSourceAndAcquire` 必须同时核对失败镜像版本及主来源已完成等事实。审计失败撤销来源版本和镜像状态；重放旧版本返回冲突且不重复审计。来源与区间随父记录删除，区间保存仅允许 fetching，不得撤销取消状态。

## 8. 后台扫描、并发与唤醒

Recover 只返回持久化待办，不开始下载、提取或清理。按 ISOID、Role、Kind 排序；只恢复 acquiring 的待获取来源，以及 acquiring/importing 且所有必需来源已完成的导入。上传 ResumeFetch 表示等客户端分片，后台不能把它当作远程下载。

Start 先检查恢复读取，再启动循环；重复 Start 成功但不增加循环。Close 取消并等待已启动的循环和作业；关闭后 Start 返回取消错误。工作名额受 Workers 限制，相同 ISOID/Role/Kind 在同实例去重，不承诺多个进程之间只执行一次。

成功登记、上传、重试、重新导入后才 Wake；失败不唤醒。Wake 容量1且可合并，只唤醒恢复扫描；可靠依据始终是数据库事实。扫描也按 PollMS 周期运行，重启可补扫。

异常仍释放名额和去重标记，按100、200毫秒等原指数间隔退避；计算前把次数截到9，因此现有实际最大间隔25.6秒。成功后清除该工作的失败次数和下次重试时间。循环异常同样退避；取消立即打断等待。

异常日志使用固定消息，不打印 panic 值或用户内容。后台恢复及清理不增加外部事件、必达保证或用户审计。

### 基线验证入口

`console/media_contract_test.go` 固定十一入口、审计及危险输入顺序；`isos_test.go` 用真实来源能力检查部分创建与审计。现有媒体上传、恢复、导入以及组装、排队回滚、删除和异常恢复测试继续作为基线。`pgstore/contract_isosources_test.go` 检查真实数据库的版本、区间、审计回滚及排队边界。

## 9. 第四阶段实现边界

| 归属 | 当前责任 | 禁止承担的责任 |
| --- | --- | --- |
| 网页入口 | 解析请求、调用 Registry 十一方法、转换响应和错误 | 直接查库、调用内部 Sources/SourceControl/Deletion 或通过同包辅助函数返回旧业务 |
| 镜像应用 | 身份、错误顺序、状态、审计、恢复、删除与后台生命周期 | 直接打开文件、请求网络或启动工具；不能调用其他应用的具体服务 |
| 领域规则 | 用传入的事实判断识别、来源齐备、导入与删除条件 | 读取文件、网络、时钟或随机数；不能持有仓储或执行查询/写入 |
| 文件实现 | 受控读写、会话、摘要、发布、清理和协调锁 | 持有 Store 或 media/port 的仓储/控制接口，决定或写入 ISO/Source 业务状态 |
| 组装入口 | 构造共用能力、传递依赖、启动和关闭 | 镜像仓储调用、恢复/导入/删除流程及业务状态判断 |

能力包同时包含应用需要的仓储接口和文件会话接口，允许导入该包不等于允许使用全部接口。类型守卫识别别名、点导入、方法值、匿名接口和同包转发。正常文件事实读取仍允许；精确的 `catalog.Arch.Valid` 只检查架构值。识别、导入、删除等领域业务函数不能由文件实现调用。

领域的 `domain/media` 只复用 `domain/repository.CheckID`、`CheckSource`、`ErrInvalid` 三个纯符号。导入许可只适用于这两个精确包，相邻包和子包不能借用。应用仅使用 `io/fs.ErrNotExist` 表示缺失，以及 `io/fs.SkipAll` 结束自身递归；没有把 `fs.FS` 或文件函数传入应用/领域。

同一实例的来源锁、登记闸门连接 Sources、Deletion 和文件能力。Supervisor 使用恢复/获取/导入、来源只读与清理重试小接口；Control 成功后才 Wake，Registry 使用 Control 和 Deletion。生产连接由 `cmd/lober/app.go` 与 Wire 生成结果明确提供。

本阶段还修复过旧行为缺陷：恢复持锁期间 Close 先发取消，避免相互等待；恢复文件时合并保留主错误和恢复错误。具体失败复现及行为影响见阶段的 Task3、Task5 执行和审查记录，不能将其仅视为代码搬迁。

第四阶段删除154项旧许可，剩余107项只属于第五、六阶段。精确删除集和起点内容校验由 `archtest/media_rules_test.go` 固定。阶段验收和两道收尾审查状态见[第四阶段证据](../superpowers/reviews/2026-10-23-ddd-phase4-evidence.md)。
