# RBAC Menu Configuration and Auth Repairs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 管理员可以持久化配置五种角色的可见菜单，并修复已确认的认证、改密、路由和按钮权限问题。

**Architecture:** console 维护可信菜单目录和角色权限映射，PostgreSQL 保存每个角色选择的菜单 ID 及修订号。前端消费当前会话的角色、权限和菜单 ID，过滤本地可信路由并控制操作入口。沿用现有统一鉴权、GORM 事务审计、Wire 装配和 Vben 状态管理。

**Tech Stack:** Go 1.27.1+、Gin、GORM、PostgreSQL、Vue 3、TypeScript、Pinia、Vue Router、Element Plus、Vben、Vitest、pnpm。

**Spec:** [2026-10-16-rbac-menu-design.md](../specs/2026-10-16-rbac-menu-design.md)，用户已确认。

## Global Constraints

- 保留 viewer、operator、hook-author、hook-approver、admin 五个角色和现有 16 个权限码。
- 一个账号对应一个角色。本轮不增加自定义角色、权限码编辑器或多角色合并规则。
- 菜单可见性和操作权限分别生效：隐藏菜单禁止通过前端路由进入对应页面；它不撤销角色原有 API 权限。
- 给角色显示某个菜单也不授予任何额外写入或审批权限。
- admin 的 role-menus 必须保留，不能取消。
- 非管理员角色允许保存空菜单列表。空列表表示明确禁止进入所有业务页面，与从未配置、使用默认值的状态不同。
- 菜单目录 ID 固定为 tasks、hosts、templates、hooks、isos、tools、reports、role-menus；配置按目录顺序规范化。
- 菜单配置变化和账号角色变化在下次导航、窗口重新聚焦时读取最新 /user/info 并生效；停留页面通过不重叠的 30 秒检查更新。
- 配置更新与 role.menus.update 审计在同一事务提交。
- 口令更新与 user.password.change 审计在同一事务提交；成功撤销该用户所有会话。
- 前端只加载本地已知路由组件；后端不返回任意组件路径。
- 本轮不新增报表统计后端，不实现已有 taskControlStub 所代表的第 7 层装机执行状态机；鉴权通过后真实业务仍按现有能力返回结果。
- 工作区已有未提交改动不回退、不混入功能提交；运行测试时不输出 .pgtest.dsn 或配置口令。

## Review Focus

1. 同时首次保存同一角色，rev=0 也只能一路成功；任务 1 以两个并发事务验证。
2. 账号切换或导航期间返回旧 /user/info，不能覆盖新账号状态；任务 4、5 用延迟响应验证。
3. 首次改密与管理员重置密码并发，新密码不得被旧请求覆盖；任务 3 用真实凭据门和修订号验证。
4. 菜单撤销时旧路由、打开的标签和缓存页面必须移除，空菜单不能循环重定向；任务 5 通过真实 Router 验证。
5. 断网退出或权限刷新失败不能伪装成功，也不能在 401 重认证与 logout 之间递归；任务 4、5、9 验证失败、恢复和重试。
