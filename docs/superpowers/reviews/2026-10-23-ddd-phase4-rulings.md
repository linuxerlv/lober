# 本阶段执行判断及误判代价

按执行记录中判断的出现顺序整理。每条说明若判断有误会造成的影响；原记录与证据保留。

1. 以当前 dev 的任务执行行为为兼容基线，旧设计中的“不可执行”描述视为历史。误判会影响任务功能。
2. 第一项只固定已有行为，不人为制造失败；后续新能力先证明缺失。误判会漏掉测试空洞。
3. 文件会话接口只有在证明原接口无法保留执行顺序时才能调整。误判会改变字节或状态处理。
4. 新隔离目录复用现有测试库连接，运行前核实实际数据库。误判会连错数据库。
5. 保留仅管理员可写镜像，纠正计划对操作员权限的误写。误判会扩大权限。
6. 审计字段保留原来的空 Detail，不新增不存在的 TargetID。误判会影响审计归属。
7. 先提交固定候选，再独立审查，通过后才可交付。误判会审查到漂移代码。
8. 管理员八项有效写入的补测移到第六项完成。误判会漏掉应用层错误拒绝。
9. 上传会话增加实际长度 Size，不能用请求声明长度替代。误判会确认错误区间。
10. 写入同步后，仍按原顺序保存区间、复查状态、显式关闭再发布。误判会丢进度或提前发布。
11. 只给旧导入测试的完成标记加同一把锁，保留所有原断言。误判会掩盖真实并发错误。
12. 媒体读取接口增加目录条目事实，业务层据此判断 Debian 仓库。误判会漏校验或下放业务规则。
13. 格式解析和复制留在文件实现，平台选择及可用性判断留在业务层。误判会留下分散规则。
14. 增加 BeginPrepare，仅准备自有临时目录，保留原错误顺序。误判会改变报错或复用错误目录。
15. 删除校验复用三个已有纯校验符号，不持有仓储。误判会引入数据库耦合。
16. 修复已复现的启停死锁：关闭先取消，恢复后复查取消。误判会造成启停竞争。
17. 只精确允许镜像领域引用上述三个纯符号，同时补类型检查。误判会放宽整个领域边界。
18. 第五项只改七个测试后，按逐文件相同证明复用已通过结果，再验证受影响范围；第六项仍跑完整命令。误判会留下覆盖缺口。
19. 网页源码未变时执行后端契约类型检查，不把缺依赖的完整 Vue 检查写成通过。误判会漏掉网页问题。
20. 应用层只允许 fs.ErrNotExist、fs.SkipAll 两个纯值，仍禁止直接读文件。误判会留下文件操作后门。
21. 第六项自查的别名、括号和复制类型遗漏必须补真实失败反例、修正并重新完整验收。误判会留下检查绕过或混用证据。
22. 最后一行包注释只做VM格式检查、逐文件及可执行内容比对，不重复全套。误判会漏掉混入的执行代码，因此另做独立局部复审。
