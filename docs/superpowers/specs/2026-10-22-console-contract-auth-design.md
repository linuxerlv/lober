# 控制台契约、登录、角色与主机编辑统一设计

日期：2026-10-22。

状态：设计草案，待用户审阅。本文没有宣称功能已经实现，也不是可立即执行的实施计划。

## 1. 已确认的需求与本次调整

1. 前后端使用完整、可检查的同一份接口契约，允许双方独立开发和使用模拟服务测试。
2. 控制台采用 JWT 访问凭据，并提供无需用户重复输入密码的自动续期、真正生效的退出。
3. 密码修改放在个人设置中。个人设置采用左侧导航、右侧内容的布局，参考用户提供的截图。
4. 同时梳理接口表示、业务对象、数据库记录，解决旧前端模型与现后端模型不一致的问题。
5. 固定三个角色：管理员、运维、访客。管理员拥有全部视图和操作；运维使用制品、装机任务、hook、模板；访客读取这四类内容。
6. SN 是主机唯一身份。按用户最后一次更正，保留表格行后的“编辑”：其他属性保存后覆盖该 SN 的旧属性；SN 不提供编辑入口，登记错 SN 时删除重建。

以下内容是本方案的建议，不能当作用户已经逐项批准：令牌时限、旧角色迁移方式、审批限制、任务提交的一致性处理、具体接口和模型字段。

本设计替代 2026-10-16 方案中的“五角色”和“内存会话”决定。原五角色菜单实施计划必须重写，不能照旧执行。用户工作区中未提交的总设计及模型重构文档不由本次覆盖。

## 2. 方案选择和拆分

| 方案 | 如何开发 | 取舍 |
| --- | --- | --- |
| 契约先行，推荐 | 先评审可机器读取的契约，再生成两端类型、调用代码和模拟基础 | 前后端可以同步开工；需要增加生成和一致性检查 |
| 后端代码生成契约 | 后端完成后，由反射生成接口说明，前端再跟进 | 沿用现有做法，但无法充分支持前端提前开发 |
| 手写接口说明及两套类型 | 两边按文档分别维护 | 重复维护继续存在，不采用 |

实施拆为四个顺序有依赖的部分，每部分应有独立的实施任务和验收：

1. 盘点模型、固定契约和默认权限，建立生成与契约检查。
2. 实现持久化登录、续期、退出以及三角色迁移。
3. 对齐业务页面，交付个人设置和主机编辑。
4. 完成独立模拟测试、真实前后端联调和旧数据升级验收。

不在本轮顺带实现装机执行状态机、完整报表后台、自定义角色或任意权限编辑器。现有未实现的任务控制能力必须在页面和测试中如实显示。

## 3. 契约的唯一来源

建议目录：

```text
api/console/openapi.yaml        所有控制台请求、响应、状态码和鉴权要求
api/console/policy.yaml         三角色权限与默认菜单的唯一数据
api/console/examples/           可校验的成功与失败示例
api/console/scenarios/          登录、过期、冲突、分页、上传等模拟场景
docs/contracts/console.md       由契约生成的阅读版说明
```

OpenAPI 是机器可以读取的接口说明。建议锁定 3.1.2，先验证生成工具的兼容性，不为追求最新版本额外升级全部工具。

契约生成 Go 请求/响应类型、服务端接口声明和 TypeScript 类型、调用方法。业务处理和页面交互仍手写，生成文件不能手工修改。已有 `openapi.go` 反射生成器退出“契约来源”的位置；运行时 `/openapi.json` 返回随发布打包的同一份契约。

每个操作有稳定的 operationId，声明请求媒体类型、入参、响应、可能状态码，以及权限和审计动作。服务端路由注册必须与契约逐项对账，不能留出“代码有接口但契约没有”的旁路。

权限和默认菜单从 policy.yaml 生成两端常量及测试矩阵。前端当前用户权限以服务端响应为准，不自行维护另一套角色名单。页面组件路径只在前端可信代码中定义。

契约先按功能完成并评审，然后对应前后端可以并行开发。契约变动必须同时更新示例、生成结果和对应测试。新增可选响应字段允许兼容扩展；改字段含义、删字段或改类型属于破坏兼容的变更，不能悄悄发布。

继续使用 `/console/v1` 及现有规范字段，如 `sn`、`hostSN`、`isoID`、`templateID`、`rev`。旧前端的 `hostId`、`artifactSetId`、`formData` 不能成为第二套后端表示。若存在已发布的外部调用方，实施前先盘点，破坏其契约的变更另开版本；不能把旧前端已失配当作允许任意改接口的理由。

### 3.1 通用规则

- 普通成功响应沿用 `{code: 0, data, message: ""}`。失败使用实际 HTTP 状态码，保留结构化问题列表，并增加稳定的 `reason` 字段供程序判断；前端不能按中文提示内容判断错误。
- 列表统一 `{items: [], next: ""}`。每个列表明确分页参数、默认值、最大值、过滤条件和顺序。空数组返回 `[]`，空对象返回 `{}`；允许为空的字段逐一声明。
- 时间沿用 Unix 秒，即从固定起点算起的秒数；版本 `rev` 为正整数。更新成功返回最新值与新版本。
- 请求类型区分“创建”“修改”“查询结果”，不让客户端传入作者、创建时间、密码散列或服务端状态。
- CSV 上传、文件分片、CSV 导出、事件流分别声明真实媒体类型和必要请求头，不伪装成普通 JSON。
- 未登录为 401，无权为 403，版本或状态冲突为 409，内容不合业务规则为 422。首次必须改密使用 403 和 `reason=password_change_required`。
- 过期凭据、被撤销会话、错误密码用不同的 `reason`。只有允许续期的过期情况触发自动刷新，不能所有 401 都无限重试。

### 3.2 全部业务面必须纳入契约

下表是盘点清单，不代替最终 OpenAPI 中逐操作的字段定义。

| 业务面 | 路径和必须约定的内容 |
| --- | --- |
| 登录 | `/auth/login`、`/auth/refresh`、`/auth/logout`，响应、Cookie、续期竞争、撤销和失败 |
| 当前用户 | `/user/info`、`/user/profile`、`/user/password`、`/user/sessions`，个人资料与账号安全 |
| 用户管理 | `/users`、`/users/{username}`，三角色、停用、管理员重置密码及最后管理员保护 |
| 主机 | `/hosts`、`/hosts/{sn}`、`/hosts/import`，创建、按 SN 编辑、删除、CSV 预览与导入 |
| 制品 | `/isos` 及详情、来源、进度、上传、取消、重试、重新导入、废弃、删除；不沿用旧 ArtifactSet 模型 |
| hook | 身份与版本分开；版本路径包含 `{id}/versions/{version}`；草稿、提交、校验、审批、驳回和废弃 |
| 模板 | 身份与版本、派生、插槽、预览、提交、审批、驳回和废弃；引用固定 hook 版本 |
| 建任务向导 | `/wizard/hosts`、`/wizard/isos`、`/wizard/templates`、`/wizard/params`、`/wizard/tasks`，多主机整批提交和逐主机错误 |
| 任务 | `/tasks`、`/tasks/{id}`、事件、事件流、预览、取消和重试；列表、快照与操作原因 |
| 审计 | `/audit`、`/audit/export`，过滤、分页、导出全量及表格公式安全 |
| 能力目录 | `/catalog`，前端所需系统系、架构、固件、参数类型、状态和能力，由后端目录生成，避免页面再抄一套 |
| 工具页面 | 复用真实模板预览与校验接口，不在页面写第二套渲染规则 |

每个操作至少有成功、参数错误、无权、状态冲突的适用示例。另覆盖空列表、最后一页、并发冲突、首登改密、续期失败和事件流重连。模拟场景引用这些已校验示例，不另外手写一套响应类型。

## 4. 业务模型、数据库模型和接口模型

保留三种表示的职责：业务对象表达装机规则；GORM 模型表达表和关联；接口对象表达网络字段。它们通过明确转换连接，不能直接把数据库模型返回浏览器。

| 对象 | 身份和关系 | 必须保持的规则 |
| --- | --- | --- |
| 主机 Host | SN 唯一，任务用 HostSN 引用 | 不新增第二个 hostId；修改属性不能更换 SN |
| 制品 ISO | 系统生成 ID | 获取来源单独记录，提取结果属于对应 ISO；不引用模板 |
| Hook | 身份 ID，版本由 ID + Version 确定 | 身份名称可变；批准版本内容不可变；版本号不回收 |
| Template | 身份 ID，版本由 ID + Version 确定 | 固定引用 hook 版本；派生是独立副本 |
| Task | 系统生成 ID，引用 SN、ISO 和模板版本 | 一台主机最多一个未结束任务；批量提交全部成功或全部失败 |
| Snapshot | 任务内的冻结输入 | 与当前主机资料区分；不是另一条可编辑主机记录 |
| User | 不可修改的 username | 单角色；密码散列不出接口；最后一位启用管理员不能被移除 |
| AuthSession | 独立会话 ID，归属于用户 | 可撤销，可过期，进程重启后仍能检查 |
| RefreshToken | 摘要唯一，归属于一个会话 | 每次续期替换，保留已用记录以识别重复使用 |
| Audit / Event | 各自独立、追加记录 | 业务写入与审计一起提交，不能让失败请求留下成功审计 |

当前 Host 实现是 `SN/Arch/Firmware/Attrs/Rev`。已有模型重构草案还提出 IP、Hostname、MACAddress、Status、CreatedBy、CreatedAt 和任务关联。它们尚未实现，本设计不把草案误写成现状。

这次统一契约应同时纳入该字段扩展：SN 仍是唯一身份；IP、主机名、MAC 是属性，不是身份。Status 是启用/停用，不能与装机任务状态混用；CurrentTask 从任务关联读取，不能再存一份任务状态。

提升为固定字段的属性不能继续在 Attrs 中保留第二份可修改值。旧模板属性绑定通过统一取值函数兼容。IP 的历史前缀不能被截掉，创建者和创建时间不能由浏览器填写；旧数据无法恢复的历史创建信息明确标为未知。

数据库读写继续通过 GORM 模型和受限扩展完成，与已有模型重构方向一致。本轮需要的会话表、字段和升级不能成为整库重写的理由，也不能删掉既有数据库约束、审计和并发保护。

## 5. 三角色默认策略

| 内容或操作 | 管理员 admin | 运维 operator | 访客 viewer |
| --- | --- | --- | --- |
| 制品、任务、hook、模板视图 | 全部 | 全部 | 与运维相同的业务内容 |
| 制品登记、上传、重新导入、废弃和删除 | 允许 | 允许 | 禁止 |
| 创建、取消、重试任务 | 允许 | 允许 | 禁止 |
| 编辑 hook 和模板、提交审批 | 允许 | 允许 | 禁止 |
| 审批、驳回、废弃 hook 和模板 | 允许 | 允许 | 禁止 |
| 读取与预览已授权内容 | 允许 | 允许 | 允许；预览即使使用 POST 也不因此变成写操作 |
| 主机管理页面、新增、编辑、导入、删除 | 允许 | 禁止 | 禁止 |
| 任务向导选择主机 | 允许 | 允许，只读取得建任务必需的主机资料 | 不开放建任务向导 |
| 用户、系统设置、审计、管理报表 | 允许 | 禁止 | 禁止 |
| 自己的资料、密码和登录设备 | 允许 | 允许 | 允许；这是个人账号操作，不是业务写权限 |

管理员“全部权限”仍服从业务规则，例如不能删除被引用的制品、不能同时创建两项未结束任务。建议继续禁止作者审批自己的 hook 或模板，由另一位运维或管理员审批。

前端菜单、手输地址和按钮使用同一权限结果；后端逐请求独立检查。运维的只读主机选择能力不等于授予独立主机管理页面或 host:write。

旧 `hook-author`、`hook-approver` 默认迁到 viewer，并输出一次性迁移记录，由管理员决定哪些账号升为 operator。这是避免自动增加权限的建议；原有审批作者及审计身份保持原值。

旧的五角色菜单配置计划不直接实施。本轮以三角色固定默认策略交付。以后若另行开放菜单显示配置，只能缩小角色可见范围，不能授予额外操作权限；管理员始终保留全部管理入口。

测试工程师可以使用 admin 完成功能主流程，但权限验收必须另用 operator 和 viewer，直接调用接口确认禁止的操作确实返回 403。测试账号不能成为程序内置默认口令。

## 6. 登录、自动续期和真正退出

### 6.1 采用的方式

访问凭据采用 JWT，即服务端签名、有效期较短的身份凭据。续期凭据采用高强度随机值，不要求也做成 JWT；这是本地账号登录方案，不声称实现完整的 OAuth 授权服务器。

建议访问凭据有效 10 分钟。续期会话闲置 7 天过期，创建后最长 30 天，续期不能突破该上限。这些数字是本项目建议默认值，不是标准规定的唯一数值。

JWT 只包含签发者、接收方、用户名、会话 ID、凭据版本、签发和到期时间等必要字段，不放密码、散列或完整业务资料。权限每次从当前用户和固定策略取得，不能让旧 JWT 长期保留已经撤销的角色权限。

固定允许的签名算法和本地可信密钥列表，初选 RS256。校验签名、类型、签发者、接收方、有效期及必要字段，拒绝无签名和算法混用。kid 只能选择配置中的密钥，不能引导服务端访问任意外部地址。密钥配置不入库、不写仓库；支持新密钥签发、旧密钥在有效期内验签的轮换。

### 6.2 浏览器保存和续期

- 访问 JWT 仅放页面内存，不写 localStorage 或 sessionStorage。
- 续期凭据仅通过 `__Host-lober_refresh` Cookie 保存，设置 HttpOnly、Secure、SameSite=Strict、Path=/，不设 Domain；接口响应体不返回它。
- 前后端以同源方式部署，开发环境用代理和 HTTPS 保持相同行为。Cookie 登录、续期和退出检查可信 Origin，缺失时校验 Referer；两者不能证明可信来源就拒绝，不能靠宽泛跨域配置绕过。
- 刷新页面时，先尝试一次续期恢复登录。正常请求临近过期时自动续期；收到允许续期的过期响应时最多续期并重试一次。
- 同一页面的请求共用一次刷新任务；多个标签页使用浏览器共享协调器串行刷新，并通知最新登录状态。运行目标浏览器必须验证该协调能力，不能直接让多个标签页同时消耗同一个续期凭据。
- 事件流使用可带请求头的 fetch 连接。续期后按最后事件序号重连，不把 JWT 放到网址中。

### 6.3 服务端会话与撤销

JWT 本身不能完成“退出立即失效”。服务端持久化会话，每次业务请求同时检查签名、会话是否有效、用户是否停用和凭据版本是否一致，不只看令牌到期时间。首版不加可能延迟撤销的会话缓存。

AuthSession 记录会话 ID、用户名、创建时间、最近续期时间、闲置及绝对到期时间、撤销时间。RefreshToken 记录会话、凭据摘要、签发/到期/使用时间和状态。数据库只保存续期凭据摘要，不保存可直接使用的原值。

续期在事务中锁定用户和会话，确认账号及凭据版本，消费旧续期凭据并写入新摘要；旧值再次被使用时撤销该会话整条续期链。重复使用的撤销结果必须提交，不能因为最后要返回 401 就把撤销事务回滚。

改密、管理员重置密码、停用账号和撤销全部设备会递增凭据版本并撤销相应会话。登录和续期最终发布前核对当前凭据版本，防止并发改密后又签出有效的旧会话。

退出允许用有效续期 Cookie 撤销当前会话，即使访问 JWT 已过期也能完成。重复退出按已退出成功处理；成功后清除同属性 Cookie，通知其他标签页清理状态。网络失败明确提示，提供重试，不能把服务端尚未撤销显示为成功。

刷新响应丢失时，浏览器再次使用旧凭据可能导致会话被撤销并要求重新登录。这是严格轮换的已知代价；不得为掩盖此情况无限接受旧凭据。

### 6.4 认证与个人接口

| 接口 | 行为 |
| --- | --- |
| POST `/auth/login` | 用户名密码登录；返回 accessToken、accessTokenExpiresAt、当前 user；设置续期 Cookie |
| POST `/auth/refresh` | 消费续期 Cookie；返回新访问凭据和当前 user，替换 Cookie；不自动调用自己 |
| POST `/auth/logout` | 撤销当前会话并清除 Cookie；不因访问 JWT 已过期而无法退出 |
| GET `/user/info` | 当前 username、displayName、role、permissions、passwordChangeRequired、rev；不再另设 `/auth/codes` |
| PATCH `/user/profile` | 只改当前用户允许修改的个人资料；检查 rev，不接受角色和其他用户名 |
| POST `/user/password` | 验证旧密码，写新密码，清除强制改密状态；审计与撤销全部会话一起提交 |
| GET `/user/sessions` | 列出本人的有效设备会话，不返回任何令牌或摘要 |
| DELETE `/user/sessions/{id}` | 撤销本人的指定会话，不能操作其他用户的会话 |

个人改密成功后重新登录。管理员重置密码与个人改密使用不同请求，不能通过个人接口修改角色或禁用状态。Vben 所需的 roles 数组、realName 等框架字段只在一个前端适配函数中转换。

## 7. 个人设置页面

从头像菜单进入 `/settings/profile`。页面左侧是固定设置导航，右侧随选项显示内容；窄屏将侧栏折叠为可选择导航。采用现有主题、间距和表单组件，不复制截图中与 Lober 无关的菜单。

| 左侧选项 | 右侧内容 |
| --- | --- |
| 个人资料 | 只读用户名和角色；可修改显示名称 |
| 账号与安全 | 修改密码；当前设备及其他设备会话；撤销指定设备 |
| 外观 | 复用现有主题等可用偏好设置，不再建一套重复配置 |

首次登录必须改密时，进入同一套设置中的“账号与安全”，明确提示先改密。该状态只允许读取当前用户、修改密码、退出和必要的续期；不能进入业务页，也不能绕到个人资料接口修改其他内容。

所有已登录角色均可进入自己的设置。个人设置不受业务菜单隐藏影响，首次改密与登录跳转不能形成循环。

## 8. 主机表格编辑与数据一致性

主机管理表格的操作列提供“编辑”和“删除”。编辑打开表单，SN 只读，其他可维护属性可修改；保存后刷新该行。入口与提交都检查 host:write，按三角色默认策略仅管理员有该权限。

创建信息和任务历史只读，不在表单保存范围。固定属性与自定义属性通过同一表单提交。输入为空表示清空可选属性，删除自定义键表示移除该属性；请求契约必须明确整条替换的语义，不能把“没传”和“清空”混成同一件事。

PUT `/hosts/{sn}` 以路径 SN 定位当前主机，提交可修改属性和读取时的 rev。成功时用新属性替换旧属性，rev 加一并返回最新主机。若有其他人先修改，返回 409，保留当前编辑内容并让使用者重新读取、确认，不能静默覆盖另一位操作者的新修改。

CSV 导入保留相同 SN 更新资料的能力，预览清楚标识“新建/覆盖已有主机”。确认导入才覆盖；不通过 CSV 偷换 SN。

SN 写错时删除旧登记，再登记正确 SN。已有任务引用时继续返回明确的引用说明，不能静默删掉历史任务；不在本次顺带引入隐藏的软删除或级联删除。删除受阻时仍可修正其他属性；确实需要处置错误 SN 的历史关联时，应另行设计保留审计的管理流程。

### 8.1 当前资料与任务中的数据

当前主机记录由新属性覆盖旧属性。已创建任务的快照按原设计保持不变；该快照记录当时确认的安装输入，不是主机当前资料的副本缓存。修改主机不应让正在安装的任务中途改变网络或磁盘参数。

尚未提交的新任务必须使用提交时最新主机资料：服务端读取资料、求值并构建快照后，仓储提交时核对构建所用的主机 rev；若发生变化，由服务端重新读最新值并重建，最多自动重试 3 次。仅在资料持续变化时返回明确冲突，不能把前一次生成的旧快照直接保存。

主机版本是提交前提，不加入机器实际下发的快照格式。批次任意一台变化就整批重建；重试不得造成重复任务或重复审计。真正写入时仍在锁住最新记录的事务里重跑准入和引用约束。

## 9. 独立开发、模拟测试和真实验收

模拟数据允许独立开发，但不能由两边任意造出各自都能通过的结果。示例和场景必须通过同一契约检查。

1. 前端用按契约生成的模拟接口，运行浏览器端到端测试，即从登录到页面操作的完整流程。覆盖三角色、首次改密、续期、退出、表格编辑、分页和错误提示。
2. 后端用同一契约校验真实请求和响应，用真实测试数据库验证写入、审计、撤销和并发；数据库不能被模拟结果代替。
3. 若后端有外部下载或其他服务依赖，可独立模拟那些外部服务；前后端各测通过不能代替真实前后端联调。
4. 真实联调至少覆盖：admin 登录、强制改密、刷新页面恢复、访问凭据过期自动续期、多标签页续期、退出后旧凭据被拒绝。
5. 主机覆盖更新后重新读取正确；SN 不可修改；失去权限不能保存；并发编辑有明确冲突；新任务取最新资料，既有任务内容不随编辑变化。
6. 验证访客不能业务写入、运维不能管理用户和主机；管理员测试账号不能掩盖这些权限检查。
7. 验证续期重复使用、退出与续期竞争、改密与登录竞争、Cookie 保护、事件流重连、刷新响应丢失。
8. 在提交检查中加入契约格式校验、示例校验、生成漂移、路由及权限对账；再运行适用的 Go、竞态、架构、前端类型检查、页面测试和生产构建。

升级从现有数据库原地进行，不删库：增加会话表和凭据版本，迁移旧角色，按模型扩展迁移主机属性。旧任务快照保持可渲染。切换后原内存令牌失效，用户重新登录；发布说明必须写明这一点。

## 10. 公开参考与项目选择

- [OpenAPI 3.1.2](https://spec.openapis.org/oas/v3.1.2.html)：用于描述请求、响应和示例。它不替项目定义业务行为，状态流转和场景仍需明确编写。
- [JWT 安全实践 RFC 8725](https://www.rfc-editor.org/rfc/rfc8725.html)：签名算法、签发者、接收方和不同令牌类型的验证依据。
- [RFC 9700 第 4.14 节](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.14)：参考其续期凭据轮换、重复使用检测和撤销机制；本项目本地登录不冒充完整 OAuth 实现。
- [OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)：参考 Cookie 保护和浏览器凭据存储建议。
- [OWASP 跨站请求防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)：参考可信来源校验；SameSite 不能代替对来源和部署边界的明确约定。

设计自检：已区分用户明确需求与建议；没有把主机 SN 和数据版本混为一谈；没有保留第二套角色或接口来源；没有把模拟测试当成真实联调；待本文评审通过后，再编写可执行实施计划。
