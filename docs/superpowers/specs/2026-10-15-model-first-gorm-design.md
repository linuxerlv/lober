# 以模型实例为中心的 GORM 存储层重构

日期：2026-10-15

状态：用户已确认设计方向与 Host 扩展；按用户补充允许第三方库及 ORM 扩展，待实施计划审阅。本文不是已经完成实现的报告。

## 目标与边界

用户要求：尽可能重构，必须使用 ORM 操作模型类，修改模型实例后再读写数据库，拒绝手写 SQL 操作数据库。

用户再次明确：以 Java 数据访问框架 / C# EF Core 的统一入口为参照，优先使用 ORM；GORM 能力不足时可以使用第三方库或扩展 ORM。因此本次目标是统一的模型、关联与查询表达式访问体系，而不是禁止 ORM 内部生成 SQL。

本次覆盖仓库自有的生产代码、测试和测试夹具。除下文用户追加的 Host 字段扩展及其对应校验/API 调整外，公开的 store 接口、业务校验、错误契约、审计原子性、版本分配和分页语义保持不变。第三方 GORM 和 PostgreSQL 驱动内部生成的 SQL 不属于手写 SQL；连接池设置、Ping、关闭连接以及事务隔离级别配置继续使用现有资源管理 API。

允许的声明是模型的 TableName、字段名、关联名、字段类型、索引和 CHECK 等 GORM 模型标签，以及用于校验数据库定义的预期元数据。数据库结构由 GORM Migrator 从模型声明生成；它缺少的 PostgreSQL 能力允许由独立、可测试的 ORM 方言/迁移扩展补齐。

能力选择顺序：GORM 原生模型及关联 API → 已验证的官方/第三方扩展 → 仓储内独立的 ormext 包。初选官方 gorm.io/datatypes v1.2.7 补齐 JSON 查询，最终以锁定版本源码及 PostgreSQL 测试验证。扩展可实现 clause.Expression、Clause Builder、Plugin 或 Migrator，但公开接口只接受模型、结构化字段/关联、受限操作及参数值，不能提供任意 SQL 字符串的逃生口。生成标识符必须引用，值必须绑定参数。业务代码不能接触扩展内部的语句生成与执行细节。

明确禁止：

- 业务仓储、控制器和普通测试绕过模型调用 Raw、Exec、驱动 Query/QueryRow/Exec/Prepare。
- 业务代码使用字符串形式的 SQL 条件、JOIN、排序、子查询和更新表达式，包括 gorm.Expr、clause.Expr、NamedExpr。
- 把现有整条业务 SQL 原样搬进 helper 或第三方包装库，伪装成 ORM 扩展；业务专用 SQL 模板不属于允许的通用表达式/方言能力。
- 用更新 map 或数据库算术表达式代替读取和修改模型实例。
- 为消除 SQL 而删除数据库约束、结构漂移检查、并发测试或事务回滚测试。

## 方案取舍

1. 只把 Raw/Exec 换成字符串 Where、Expr：改动小，但不满足要求，排除。
2. 使用模型实例、GORM 内置结构化条件和模型关联；缺少的表达能力使用第三方库或独立 ORM 扩展：满足要求，选用。不为规避表达式生成而新增查询投影表或排序字段。
3. 读取整张表后在 Go 中完成所有查询：能减少数据库表达式，但破坏分页规模和查询效率，不采用为正常业务路径。

## 模型实例的读写规则

新增：构造完整模型实例，通过 Create/CreateInBatches 写入。删除：先按模型条件查出记录，再 Delete 对应实例。更新：在事务中查出并锁定模型，检查 Rev 与业务约束，修改同一实例的字段，通过显式字段选择的 Updates 保存该实例，最后写审计。

显式选择更新字段是为了包含 false、0、空字符串等合法零值，并防止意外写入主键、CreatedAt、关联或只读字段。不使用 Save 在更新零行时自动插入的回退行为。批量修改仍然基于查出的每个模型实例；批量读取和插入可以继续使用 ORM 批量 API。

简单条件使用模型/map 作为查询条件；范围、集合和组合条件使用 GORM 内置 Eq、Neq、Gt、Gte、Lt、Lte、And、Or 等表达式。查询 map 仅用于过滤，不用于修改数据。模型关联使用 Preload 或关联名形式的 Joins。不能使用 SQL 文本形式的 Joins。

## 各业务模块的处理

### Host 字段与任务关联（用户追加要求）

保留现有 SN、Arch、Firmware、Attrs、Rev；增加以下明确字段及关联，不再仅靠 Attrs 表达主机基本信息：

| 字段 | 含义及写入规则 |
| --- | --- |
| IP | 主地址。输入校验和迁移必须保留已有地址/前缀语义，历史 Attrs.ip 中的 CIDR 前缀不能被静默截掉；不在此次扩展中引入多网卡管理。 |
| Hostname | 主机名，非空时按主机名规则验证；从历史 Attrs.hostname 迁移。 |
| MACAddress | 主 MAC 地址，非空时解析并统一格式；不自行假定现有数据已经满足全局唯一性。 |
| Status | 主机管理状态，独立 HostStatus 类型，取 enabled（启用）或 disabled（停用）。新建及历史数据回填默认为 enabled；不能复用 TaskState，也不表示在线/离线。 |
| CreatedBy | 创建者，从创建/首次导入的可信审计 Actor 写入；后续编辑、重新导入不得覆盖，不接受客户端伪造。 |
| CreatedAt | 创建时间，与 CreatedBy 一起从首次创建审计 At 写入并保持不变。 |
| Tasks | Host 与 Task 的一对多 ORM 关联，以现有 Task.HostSN 引用 Host.SN；不增加任务 ID 数组或 JSON 列，不允许保存 Host 时顺带改写历史任务。 |

用户已确认：分开提供主机管理状态与当前任务状态。Status 表示主机是否允许被安排新装机任务：disabled 的主机不接受新任务，已有任务继续按其状态机运行，查询、审计和历史记录仍可访问；切换管理状态必须执行 Host 的版本检查及审计。

任务列表使用关联查询和分页接口提供，主机普通列表不默认预加载全部历史任务。详情另外返回只读的 CurrentTask 摘要（ID、State、CreatedAt）：优先选择唯一未结束任务，没有未结束任务时选择按既有任务排序规则排在最前的最近任务，没有任务时为 null。CurrentTaskState 从该任务的 State 读取，不增加主机表上的任务状态列。任务列表中的历史结果与当前任务摘要不得由客户端通过保存 Host 修改。

主机表、领域模型、store 校验、Console 请求/响应、CSV 固定列、前端 Host 类型和主机详情均需同步调整。将提升为固定字段的属性从 Attrs 中移出，避免同一信息存在两份可修改值；模板对历史 ip/hostname 属性的绑定通过统一字段取值接口继续解析。激活校验、参数求值和快照构造必须同步接入该接口，不能只改表和界面。已生成的任务快照保持不可变，旧快照继续能渲染。

旧主机通过 ORM 分批迁移基本字段；创建信息从当前登记生命周期内首次创建/导入的审计恢复（若同 SN 曾删除再建，不得继承前一次登记的创建者），无法可靠恢复的记录显式保留为未知，不得用本次升级操作者或时间伪造历史。字段冲突、非法旧数据和 MAC 属性键的实际使用须在迁移前盘点并输出可定位的结果，不静默覆盖。

### Hook 与模板

移除 versioning 中依赖表名拼接 SQL 的 joined、listQuery 等实现，改为有明确模型类型的 Hook/模板查询。身份名称通过模型关联取得，不再将手写 SELECT 列别名映射为额外字段。

最新版本、最新已审批版本由 GORM 模型子查询构造：按所属身份结构化关联，按 version 倒序并 Limit(1)，避免手写 SELECT max(...)。表别名只能通过 GORM 内置的结构化表/列描述表达。实现前用 GORM DryRun 验证关联子查询的构造能力，随后由真实 PostgreSQL 契约测试验证；不能退回字符串 SQL。

身份的 LastVersion 仍然单调递增，删除草稿不回收版本号。名字唯一、内置版本只读和审批时重跑业务校验等规则保持不变。

### 原子更新与并发

- ImportHosts：按既有 SN 字节序处理主机；不存在的模型可用内置 OnConflict DoNothing 建立记录，再锁定并读取实际模型，按新建/已有路径更新字段及 Rev。必须在同一事务中正确识别新建记录，且保留批量输入去重和错误契约。不能先查不存在就直接插入并假设没有并发竞争。
- SaveRange：继续先锁定来源模型，读取已有范围模型，在 Go 中比较长度并修改模型，保存范围及来源 Fetched/Rev。禁止 GREATEST 表达式；重传较短范围不得减少已确认长度。
- 用户：增加固定的仓储互斥模型记录。启动以 GORM 原生冲突处理确保其存在，所有用户创建和更新先锁定同一记录，再锁定目标用户。查询有效管理员并执行保护规则，修改用户模型后保存。顺序必须统一，且互斥必须在数据库中跨进程生效。
- 任务状态、事件序号、身份版本号等其他更新也统一修改已锁定实例。保留 READ COMMITTED、现有实体锁定顺序和审计事务。

### 排序、前缀与 JSON 查询

不能直接删除 COLLATE C，也不能依赖部署数据库的默认排序。由 ORM 扩展提供结构化的 C 排序字段及比较表达式，供排序、游标过滤、稳定选取和锁顺序共用。不增加 bytea 排序键，不改现有游标格式。

前缀查询通过 ORM 的受限 Prefix(column, value) 表达式构造，在 PostgreSQL 方言中生成参数化 starts_with 调用；保留百分号、下划线和反斜杠的字面语义。业务代码不拼接函数文本或 LIKE 模板。

Host.Attrs 的键值筛选和 Template.Series 的包含筛选优先使用经锁定版本验证的 datatypes.JSONQuery / JSONArrayQuery；需要结构化限定列名时，由 ormext 提供窄包装或等价表达式。保留原 JSONB 模型与 nil/空集合的往返语义，不新增重复投影数据，不加载全表后过滤。JSON 更新仍读取并修改模型实例，不使用 JSONSet 绕过模型值修改。

数据库方言、表达式和第三方依赖不向 core/model 或 store 契约泄漏；Host 的公开字段扩展按前述用户追加要求处理。

## 结构校验与升级

保留 AutoMigrate 和启动时结构漂移检查。优先使用 Migrator 的索引、列及约束接口；其不能提供的信息，通过映射 PostgreSQL 系统目录/信息模式视图的只读模型及 ormext 的受限数据库函数表达式获取，在 Go 中组装并比较元数据。不能保留 schema.go 中整条手写 SELECT。

需要完整保留：主键列及顺序、索引唯一性和列顺序、部分索引谓词、外键目标 schema/表/列、删除动作、CHECK 定义，以及多余索引和约束检测。数据库视图返回的定义文本是待比较的数据，不是待执行的 SQL。模型必须限定当前目标 schema，不能把同名的其他 schema 表算进来。不能通过 HasConstraint 代替定义一致性检查。

升级采取加法迁移：先由模型建 Host 新增字段和用户互斥表，在对外服务前以 ORM 分批迁移旧主机数据并初始化互斥记录，再启用新查询。回填必须可重入，重复启动不得重复增加业务 Rev 或写入业务审计；失败时拒绝启动。现有数据库须支持升级，不能要求删库重建。迁移 API 缺少的通用 DDL 能力由受限 Migrator 扩展实现，不能开放执行任意 DDL 文本的接口。

## 测试夹具与故障注入

普通数据准备、白盒读取、修改异常业务数据和持有行锁全部改为 ORM 模型实例操作。结构破坏测试使用独立测试模型与 GORM Migrator 的 Create/DropIndex、Create/DropConstraint 等能力创建预期偏差，保留每类漂移的拒绝启动断言。

测试的审计失败注入改为仅在测试仓储构造时安装的 GORM 回调：在指定模型写入时返回测试错误，验证同一真实数据库事务中的业务写入回滚。正常生产仓储不安装该回调；不能加入生产模型中根据 Actor 特殊值拒绝写入的逻辑。队列失败等其他触发器测试也改为对应模型的测试回调。回调不能代替数据库唯一键、外键和 CHECK 失败的集成测试。

保留现有每用例独立 schema 的隔离方式及连接数限流。建删 schema 通过 ormext 的 PostgreSQL Migrator 扩展提供 CreateSchema(name)/DropSchema(name, cascade)；名称由测试夹具生成且由方言引用，不接受 DDL 文本。不再直接使用 pgx.Connect/Exec。search_path 通过现有 DSN 参数设置，不执行 SET 语句。

保留生产和测试的现有表名、索引名及约束名，避免引入全套动态 NamingStrategy 重构。迁移扩展先验证两个并行 schema 的隔离与安全清理，再迁移全部夹具；不得删除非本次测试分配的 schema。

并发测试通过独立 ORM 事务和已知模型锁制造等待；必须查询服务器状态才能确定的断言，通过只读 pg_stat_activity/pg_locks 等模型及受限函数表达式读取并在 Go 中关联，不能用固定 sleep 替代等待条件。为同一测试 schema 重新打开仓储时，沿用其 DSN。

ORM 元数据或测试管理能力不足时，按用户授权补充第三方库或 ORM 扩展；仍不能保持现有功能时报告具体能力缺口，不能静默恢复业务 SQL 或删除覆盖。

## 架构门禁

增加基于 Go AST 和类型信息的守卫，覆盖生产、测试及夹具：禁止绕过模型直接驱动访问、Raw/Exec、SQL 文本条件/联表/排序、Expr 和 map 更新。允许模型名字、字段/关联选择、模型标签及预期元数据。方言级表达式生成及迁移执行只允许在独立 ormext 内部；该包不得向外暴露任意 SQL 文本入口，不得依赖业务实体或控制器。守卫需识别导入别名、字符串变量和常量传递；不能仅靠关键字 grep。

pgconn.PgError 作为数据库错误解码类型继续保留；database/sql 仅允许连接资源管理和事务选项。架构规则放行受限 ormext 包和锁定的 ORM 扩展依赖；扩展不能持有第二套原生驱动连接池。调用 GORM、第三方 ORM 扩展及已审查的方言组件生成查询和迁移 SQL 不属于违规。

## 验收

- 所有仓库自有数据库访问经 GORM 模型、关联及受限 ORM 扩展完成；业务和普通测试无手写 SQL、无扩展隐藏的任意 SQL 入口。
- 原有 store 契约全部通过，包括零值更新、nil/空集合、名称前缀特殊字符、跨页稳定性、复合版本键、版本号不回收。
- 并发覆盖管理员交叉禁用、并发主机导入、同来源上传重试、同任务事件 Seq、审批与任务准入、外键引用删除及审计回滚。
- 结构漂移检查保持完整覆盖，旧数据升级可重复执行，回填后新旧查询结果一致。
- Host 新字段完成 API/CSV/前端同步；创建者不可伪造或被编辑覆盖，旧 ip/hostname 模板绑定保持可用，任务列表分页且任务历史不随主机保存被改写。
- 主机管理状态与任务状态独立：停用阻止新建任务，不能取消或篡改已有任务；CurrentTask 优先未结束任务、其次最近任务、无任务时为空，状态只取自对应 Task。
- 运行格式检查、go vet、架构守卫、完整 PostgreSQL 测试、race、Linux 交叉构建和 Wire 漂移检查；检查失败要报告原因，不能跳过或宣称通过。
- 保留当前工作区中已有的渲染、ISO、测试及文档改动；本重构不能覆盖其他工作的修改。
